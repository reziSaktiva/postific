## How to use

1. Pick one ID from the table below.
2. Open **one** file named by the File column and jump to that ticket's heading. Release tickets live in `tickets/vXX-*.md`. Tickets born from a Known Issue live in `tickets/known-issues.md` (ADR-134). S-004 tickets live in `tickets/s004-orchestration-language.md` and S-007 tickets in `tickets/s007-documentation-language.md`. Follow the **Docs** / **Read first** field. Do not sweep the `tickets/` folder.
3. If the work spans several sessions and no spec exists yet, write `specs/S-NNN.md` first. Existing specs: S-001 (MCP Server MVP), S-002 (QA E2E Playwright), S-003 (wave-based AI orchestration), S-004 (AI orchestration language, decision 2026-11-11, T-234 to T-246), S-005 (Draft Editor redesign in the Buffer pattern, Stage 1), S-006 (per-post Engage in the Buffer pattern), S-007 (layer 3 document language, draft 2026-11-12).
4. When done: status ✅ in its ticket file, and its row is removed from this table. Do not add session notes.

Phase and blockers are in [`PROJECT_STATE.md`](PROJECT_STATE.md). An open Known Issue has a row in that file's KI table, and its ticket is here.
