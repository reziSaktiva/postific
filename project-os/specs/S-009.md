# S-009 · Infinite scroll for long lists

**Docs:** ADR-166 (Accepted), ADR-165, ADR-097, ADR-140, ADR-149, ADR-153, ADR-161, `product-discovery/04-ux/key-screen-patterns.md` (KSP-03, KSP-04, KSP-05, KSP-06, Pattern: MCP Source Badge and Filter), `apps/web/.claude/CLAUDE.md`
**Design:** `ScreenInfiniteScrollStates` in the Postific artifact, confirmed by King Rezi 2026-11-25 (gallery entry "Infinite scroll: state daftar (S-009)", reviewed section by section: Publish List, Board column, phone 390 px, Engage List, Notifications).
**Tickets:** T-301 to T-305 (`tickets/v02-publishing-mvp.md`). Split from T-298.

## Behavior

Seen from the side of the user (Raka) on a large workspace such as Cook It Real Good.

**Where it applies**

- Publish · List: History, Queue, Drafts and Approvals tabs.
- Publish · Board: each column on its own.
- Engage · List view (the inbox of posts with comments) and the comments of one post.
- Notifications panel.
- Calendar, Home, Analyze, Start Page and Settings do not change. The Draft Editor media picker is not in S-009 (it does not exist yet; ADR-166 addendum).

**Loading**

- A list first shows its newest 20 items (or the first 20 in that list's existing order). When the user scrolls near the end, the next 20 load on their own, with no button.
- While a page loads, 2 to 3 skeleton rows shaped like that list's items appear at the bottom. The rest of the list stays usable.
- When there is nothing more, a short muted line at the bottom says the user has reached the end. A list that fits in one page shows the same line, or its existing empty state when it has no items.
- If a page fails to load, an inline alert with Retry appears at the bottom; the items already loaded stay. Retry loads the same page again.
- Scrolling back up never reloads pages already shown. Items never repeat or go missing when new items arrive during scrolling.

**Counts, filters and realtime**

- Tab counts (Queue, Drafts, Approvals, History) and Board column counts show the true total, not the number loaded. The "100+" Board label is gone.
- Changing a filter (MCP source, channel or account, status, Engage filters) clears the list at once, shows the loading skeleton rows, then shows the new first page and counts for the new filter (King Rezi, 2026-11-25). A first page of an older filter that arrives late is ignored.
- A realtime change (a post published, a status change, a new comment, a new notification) updates the loaded items and the counts as today. A new item that belongs at the top appears at the top; one that belongs further down than the loaded pages appears when the user scrolls to it.
- Day grouping in the List (S-008) still works across page boundaries: a day split over two pages shows as one day heading.

**Board**

- Each column loads 20 cards and the next 20 as that column is scrolled, independent of the other columns. Phone and tablet behavior from S-008 and T-300 (one column per screen, sideways swipe) stays.

**Notifications**

- The Notifications panel loads 20 at a time; "Mark all as read" marks every unread notification, not only the loaded ones, and the unread badge stays the true unread count. Its new lines are in English, like its header (ADR-166 addendum).

**MCP**

- MCP read tools keep their current behavior (ADR-166 decision 8).

## Test seams

- A shared client hook for a paged list (first page, next page on demand, loading, end, error and retry, reset on filter change, merge of realtime changes) with unit tests, and a shared sentinel component that asks for the next page when it scrolls into view. Lives with the shared app components, built from shadcn/ui (ADR-097).
- A shared cursor shape (opaque cursor string, page of items, next cursor or none) in `packages/shared`, types only (hard rule 5).
- Repository queries in `lib/repositories/{publishing,engagement,notification}`: cursor-based pages with a stable order (sort time plus id) and separate count queries. DB integration tests where available, including two items with the same sort time across a page boundary.
- Domain services (`publishing`, `engagement`, `notification`): page in, page out; grouping (Board columns, day groups, inbox post groups) works on a page. Unit tests with local doubles (`AGENTS.md` rule 11).
- Entry points only call services (hard rule 3): the first page from the RSC, every next page from a GET Route Handler per list (ADR-166 addendum 5; RS-D01, Server Actions stay for mutations). The Route Handler validates the cursor and answers an invalid one with an error; the client `loadPage` throws on any error so the Retry Alert shows, and never redirects mid-scroll.
- UI: Playwright E2E on Cook It Real Good (King Rezi, 2026-11-25) for each section with more than 20 items: the second page loads on scroll, counts stay true, a filter change resets the list. A section with 20 items or fewer there is recorded as not yet proven, not faked.
- Verified (staging) once per wave (ADR-153, ADR-161), in T-305.

## Out of scope

- Infinite scroll for Calendar, Home, Analyze, Start Page and Settings.
- Virtualized rendering (only drawing visible rows); revisit if a loaded list of a few hundred items is still slow.
- Paging in MCP read tools.
- Changing the order or grouping of any list.
- A "jump to date" control in History.
- The Draft Editor media picker (a feature of its own; it uses this pattern when built).
